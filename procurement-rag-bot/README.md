# 采购知识助手｜基于Coze扣子平台搭建
## 🔗 (https://www.coze.cn/store/agent/7694122642001051688?bot_id=true)

## 一、项目背景
本人拥有1年半医药采购行业实操经验，熟悉采购需求提报、供应商资料管理、采购文档查阅、合规条款核对等业务场景；后续备考公考期间持续自学大模型、提示词工程、AIGC相关知识，目标转型AI产品岗位。

本项目立足于真实采购业务痛点：采购相关文档分散（合同条款、供应商资料、内部采购规范等），人工查阅检索耗时，跨文档信息比对繁琐。
基于Coze扣子平台搭建RAG知识库智能体，将采购类文档入库，实现私有文档问答、条款检索、文档摘要、信息提取，验证大模型RAG在B端采购场景落地的可行性，同时练习智能体产品设计、提示词迭代、幻觉控制能力。

## 二、核心功能
1. 私有知识库问答：上传采购MD文档，智能体仅基于入库文档内容回答，减少大模型凭空编造信息
2. 文档信息检索：快速定位合同、采购规范里关键条款（采购流程、履约期限、合规约束）
3. 批量内容摘要：对长采购文件自动提炼核心要点，减少人工阅读成本
4. 结构化信息提取：按固定格式提取供应商名称、报价、交付周期、约束条件
5. 对话记忆：支持多轮连续提问，针对上一轮回答继续追问

## 三、项目架构 & 使用技术/平台能力
1. 平台：Coze扣子AI智能体平台
2. 核心能力：RAG知识库（文档上传、文本分块、向量召回）
3. 提示词工程：角色设定、Few-shot少样本示例、CoT思维链、输出格式约束、幻觉抑制提示
4. 编排能力：扣子工作流、知识库检索插件、多轮对话管理

## 五、产品设计思路
1. 角色定义：将智能体设定为「采购知识助手」，限定身份，避免回答脱离采购业务范围；
2. 检索策略：设置知识库召回片段数量，平衡检索精度和上下文长度，控制Token消耗；
3. 幻觉控制：在系统提示词强制约束：知识库无对应信息时，直接告知“文档内未查询到相关内容”，禁止编造不存在条款；
4. 输出规范：要求回答优先引用原文内容，关键信息标注来源文档名称；
5. 边界设计：明确能力边界，不做合同法律判定、不做采购决策建议，仅做文档信息检索辅助。

## 六、项目收获
1. 业务结合：把过往医药采购行业经验和大模型产品落地结合，理解行业场景下用户真实需求，而不是纯demo玩具项目；
2. RAG认知：理解知识库文档分块、向量检索的基础逻辑，知道RAG能解决什么问题，以及RAG天然的局限（文档质量直接决定回答质量、长文档跨章节检索容易丢失信息）；
3. 提示词实操：掌握角色设定、少样本、思维链、幻觉抑制多种提示词技巧，学会持续迭代提示词，根据测试反馈不断优化；
4. AI产品思维：学会定义智能体能力边界，区分“AI能做”和“业务可信可用”，理解大模型产品需要做约束、兜底、异常处理；
5. 落地经验：完整走完智能体从需求构思、知识库上传、提示词调试、多轮测试，直到对外发布、生成公开访问链接的全流程。

## 七、项目局限与后续优化方向
1. 当前局限
    - 文档格式限制：图片扫描版PDF无法直接识别，只能使用可复制文本的文档；
    - 长文档跨章节复杂推理能力弱，多份文档交叉比对容易遗漏细节；
    - 知识库更新需要手动上传新文档，暂无自动同步文档更新能力；
    - 没有接入外部业务数据库，只能使用预先上传的静态文档。
2. 后续优化计划
    - 优化文档分块策略，测试不同分块大小对检索结果的影响；
    - 增加结果溯源，回答中直接标注引用的文档段落位置；
    - 增加结构化导出能力，将提取到的供应商信息直接输出CSV；
    - 增加权限设计思路（产品层面思考，区分内部人员只读/编辑权限）。
