# 医药零售智能动销分析工作台 (AI Product Workflow)

> **项目类型**：AI 产品经理转行作品集（个人项目）
> **核心工具**：扣子 (Coze) 工作流、UI Builder、Prompt Engineering
> **项目定位**：一站式解决医药批发零售场景下，人工处理多维动销数据耗时长、洞察提炼难的痛点。

## 📖 项目简介

本项目面向医药批发零售业务，通过“**前端标准表单 + 后端双工作流解耦**”的混合架构，实现“数据录入 -> AI生成初稿 -> 人工审核反馈 -> 定向修改终稿”的完整自动化闭环。项目成功规避了大模型的算术幻觉与拒答反噬，落地为可公开访问的 Web 应用。

## 🎯 业务背景与痛点
*   **业务考核**：核心关注药品销售量，需多维度分析供应商和品种的动销情况。
*   **现实困境**：大模型无法处理海量原始明细，前端业务人员必须先在 Excel 进行透视和计算。
*   **核心痛点**：人工从多维度数据中提炼洞察耗时耗力；报告撰写繁琐；直接用大模型处理明细极易产生**算数幻觉**。

## ✨ 技术亮点
1.  **架构解耦设计**：将“初稿生成”与“意见修改”拆分为两个独立工作流，彻底解决带审核节点的单体工作流导致前端请求挂起超时的问题。
2.  **防算数幻觉工程**：采用“计算与生成分离”策略。强制前端输入已计算好的透视数据，并在Prompt中严格约束大模型“只做文本加工，绝不自行加减乘除”。
3.  **防御性提示词反制**：针对大模型因缺少字段而“罢工”的防御性反噬，加入了“强制生成”铁律，确保模型能在数据不完整时最大化利用现有信息输出报告。
4.  **B端UX交互体验**：使用扣子 UI Builder 搭建标准表单工作台（非聊天框），增加组件等待提示与成功/失败状态反馈，缓解用户长耗时任务焦虑。

## 🏗️ 整体架构设计 (V2.0 架构解耦)
1.  **数据输入层**：用户粘贴已算好指标的 Markdown 表格。
2.  **工作流 A (生成器)**：接收数据，输出初稿报告 (`initial_report`)。
3.  **工作流 B (修改器)**：接收初稿与人工意见，输出终稿 (`final_report`)。
4.  **UI 层 (工作台)**：绑定工作流A与B，实现数据录入与结果预览。
